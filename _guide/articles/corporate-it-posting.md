情報システム（社内SE）の求人票は、「どの領域を担当するか」「自分で作るのか、外部の会社を動かすのか」「組織の体制はどうか」「誰の社内で働くのか」の4点で読むと、求人ごとの違いがはっきりします。同じ「社内SE」でも、PCの準備や問い合わせ対応が中心の仕事と、基幹システムの刷新を企画から主導する仕事では、求められる経験も、日々の中身もまったく違います。職種名だけで判断せず、仕事内容に並ぶ業務を領域ごとに分けて読むのが基本です。

## 「社内SE」という言葉が指す範囲

情報システムの求人に出てくる業務は、大きく次の領域に分かれます。仕事内容にどの領域の言葉が多いかで、そのポジションの中心が分かります。

| 領域 | 求人票によく出る書き方 | 中心になる仕事 |
|---|---|---|
| ヘルプデスク・端末 | 「問い合わせ対応」「PCキッティング」「IT資産・ライセンス管理」 | 社員がITを使える状態を保つ。入退社のたびの準備と回収 |
| ID・SaaSの管理 | 「アカウント・権限管理」「SSO」「MDM」「Microsoft 365・Google Workspaceの管理」 | 誰が何を使えるかを管理し、入退社や異動の手続きを整える |
| インフラ・ネットワーク | 「社内ネットワークの設計・運用」「サーバー・クラウドの管理」「拠点展開」 | 社内の通信と基盤を支え、障害時に復旧させる |
| 業務システム | 「業務アプリケーションの開発」「基幹システムの運用」「ERP・SFAの導入」 | 会計・人事・販売などの業務を支えるシステムを作り、守る |
| セキュリティ・統制 | 「情報セキュリティ対策」「IT統制・監査対応」「ISMSの運用」 | ルールを作り、守られているかを確かめ、事故に備える |
| 企画・DX | 「ITロードマップの策定」「業務改善の提案」「生成AIツールの展開」 | 何に投資し、どう業務を変えるかを決めて進める |

1つの求人に複数の領域が並ぶのがふつうです。並び順や分量に加えて、必須要件にどの領域の経験が書かれているかを見ると、どこが中心かを判断しやすくなります。担当範囲の違いは[情報システム（社内SE）の仕事の範囲](/guide/corporate-it-job-scope/)で詳しく扱っています。

## 自分で作るか、外部の会社を動かすか

社内SEの求人で読み分けたいのが、システムを誰が作るかです。

- **内製で作る**：「要件定義から設計・実装・導入・運用保守まで自社内で一貫して」「社内ツールの内製開発」と書かれたもの。開発言語や、ローコードツール（Power Platform・kintone など）の記載があり、必須要件にも開発経験が入りやすい
- **外部の会社に依頼して進める**：「ベンダー折衝」「要件定義・基本設計まで上流工程全般」「ベンダー選定・投資判断資料の作成」と書かれたもの。作るのは外部の開発会社で、自分は要件を決め、品質と進み具合を確かめる
- **両方**：「既存はベンダーが保守、新しい仕組みは内製化を進める」のように、移行の途中にある求人もある。「外部の技術者からの引き継ぎ」「内製化の推進」と書かれていれば、既存の仕組みを読み解く仕事が多くなる

SIerで開発をしてきた人が社内SEの求人を見るときは、この違いが特に大事です。外部を動かす形の求人では、コードを書く機会が少なくなることがあります。考え方は[SIerから社内SEの求人に応募する考え方](/guide/corporate-it-from-sier/)、外部の会社との関わり方は[ベンダー管理を担う社内SEの求人の読み方](/guide/corporate-it-vendor/)をご覧ください。

## 組織の体制の書かれ方

情報システムの部門の大きさや位置づけも、求人票から読み取れることがあります。

- **人数の記載**：「現在の体制は◯名」のように少ない人数が書かれていれば、1人あたりの範囲は広い。ヘルプデスクから基盤、ベンダーとの窓口まで受け持つことになりやすい
- **一人目・立ち上げ**：「情シスの立ち上げ」「1人目の社内SE」と書かれたもの。ルールや仕組みを作るところから任される一方、相談できる同職種がいない場合もある（[一人情シスの求人の読み方](/guide/corporate-it-hitorijoshi/)）
- **組織の位置**：「社長室直下」「経営企画部内」「管理本部」など。どこに置かれているかで、意思決定の近さや、求められる役割が変わる
- **部門の中の分担**：「インフラチーム」「業務システムチーム」「セキュリティチーム」に分かれている会社では、1つの領域を深く担う形になりやすい

体制の読み方は[情報システム（社内SE）の求人の配属先とチーム体制の読み方](/guide/corporate-it-team-structure/)でも扱っています。

:::view
情報システムの求人は、同じ「社内SE」という職種名でも、問い合わせ対応が中心の会社と、システムの企画や刷新が中心の会社で、仕事の中身がかなり違います。求人をご紹介していると、ヘルプデスクの比重や、外部の会社との分担が求人票からは読み取れないケースをよく見かけます。こうした点は、ご質問いただければ企業に確認できます。
:::

## 誰の「社内」で働くのか

情報システムに分類される求人には、自社の情報システム部門で働く求人のほかに、別の会社の情報システム業務を担う求人も含まれます。

- **事業会社の自社部門**：会社紹介と仕事内容が同じ会社のことを書いていて、勤務地が自社の事業所になっているもの
- **顧客企業の情報システム業務を担う**：IT企業や人材サービスの会社が採用し、取引先の情報システム部門の業務を支援するもの。「プロジェクト先」「取引先」「大手企業での就業が多い」と書かれ、勤務地が配属先によって変わる
- **BPO・運用の受託**：複数の会社のヘルプデスクや運用をまとめて請け負う会社の求人。「BPOセンター」「お客様のIT課題解決の支援」と書かれる

雇用形態の欄に「無期雇用派遣」「常用型の有期雇用派遣」などと書かれている求人もあります。働く場所、日々の指示を出す人、契約の期間がどうなっているかで働き方が変わるので、会社紹介・勤務地・雇用形態の欄を合わせて読みましょう。勤務先が変わる求人の確認点は[勤務先が変わる可能性がある求人の確認点](/guide/kyakusaki-henkou/)で扱っています。

## 技術・環境の欄から読み取れること

情報システムの求人の技術や環境の欄には、会社のITの状態が表れます。

- **グループウェアとID管理**：Microsoft 365・Google Workspace、ID管理（Entra ID など）、SSO・MDMの記載があれば、SaaS中心の環境を管理する仕事が多い
- **オンプレミスの記載**：Active Directory、社内サーバー、拠点間のネットワークなどがあれば、設備のある環境の運用も範囲に入る
- **業務システム**：ERPやSFA、会計・人事のパッケージ、ローコードツールの名前があれば、業務システムの導入や改修が範囲に入る
- **統制と認証**：ISMS、IT統制、監査対応の記載は、ルールづくりや証跡の管理が仕事に入ることを示す。上場の準備を進めている会社の求人でも見かける
- **生成AIの展開**：生成AIツールの導入や社内への展開を仕事内容に挙げる求人も増えている。ツールの管理だけか、業務への活用の推進までかで中身が違う

社内のDXを掲げる求人は[社内DX推進の求人の読み方](/guide/corporate-it-dx/)、基幹システムの求人は[基幹システムを担う社内SEの求人の読み方](/guide/corporate-it-erp/)、セキュリティの求人は[社内セキュリティを担う求人の読み方](/guide/corporate-it-security/)もご覧ください。

## 応募条件と選考の欄の読み方

情報システムの求人の必須要件は、「下記いずれか」で書かれることが多いのが特徴です。「情報システム部門での実務経験」「PCキッティングやアカウント管理などの運用経験」「ヘルプデスクの対応経験」のように並び、どれか1つで応募できる形です。一方、内製の開発が中心の求人では「業務アプリケーションの開発経験」「SQLの読み書き」が、管理者の役割が中心の求人では「Microsoft 365やGoogle Workspaceの管理者経験」が求められます。

「社内関係者とのコミュニケーション」「関係部署と連携して進める力」といった条件もよく並びます。社内SEの利用者は社内の人なので、要望を聞き取り、分かる言葉で説明する場面が多いことを表しています。詳しくは[情報システム（社内SE）の求人の必須要件・歓迎要件](/guide/corporate-it-requirements/)で扱っています。

選考の欄には、書類選考と面接のほかに、適性検査や筆記試験が書かれていることがあります。面接の回数や、最終面接を対面で行うかどうかも会社によって違います。リファレンスチェックを行う会社もあります。準備のしかたが変わるので、どの段階で何をするかは事前に確かめておくと安心です。

## 働き方の欄で見ておくこと

情報システムの仕事は、働き方の面でもほかのエンジニア職と違うところがあります。

- **出社の頻度**：PCの準備や機器の交換、ネットワークの工事など、現地でしかできない作業がある。「フル出社」と書かれた求人もある
- **業務時間外の作業**：システムの更新や切り替えは、社員が使わない夜間や休日に行うことがある。頻度と、振替や手当の扱いは確かめておきたい
- **障害時の連絡**：社内のシステムが止まったときに、誰に連絡が来るのか。少人数の部門ほど、自分に来る可能性が高い

## 応募前に確かめたいこと

求人票だけでは分かりにくく、入社後の働き方に関わる項目をまとめます。

| 項目 | 確かめたいこと |
|---|---|
| 領域の比重 | ヘルプデスク・基盤・業務システム・企画の割合 |
| 作り方 | 内製と外部への依頼の割合、外部の会社との分担 |
| 体制 | 部門の人数、上司が情報システムに詳しいか、相談できる相手 |
| 働く場所 | 自社か配属先か、出社の頻度 |
| 時間 | 夜間・休日の作業や障害時の連絡の有無と頻度 |
| これから | 直近で予定しているシステムの導入・刷新、予算の決まり方 |

:::view
当社からの応募は当社への申し込み（無料）で、当社から企業へ推薦する形で選考が進みます。サイトに載せていない非公開の求人もあり、「運用から企画へ広げたい」「内製の開発を続けたい」といった希望を伺ったうえで、掲載外の求人も含めて個別にお探しできます。
:::

情報システム（社内SE）の求人は[エンジニアの求人一覧](/jobs/engineer/)で探せます。求人の傾向は[エンジニアの求人・年収動向](/jobs/engineer/market/)と、ページ下の掲載データもご覧ください。

## よくある質問

### 「社内SE」と「情報システム」の求人は違う仕事ですか？
多くの求人では、ほぼ同じ意味で使われています。呼び方より、仕事内容にどの領域の業務が並んでいるかで判断してください。「コーポレートIT」「コーポレートエンジニア」と書かれた求人は、SaaSやIDの管理、業務の自動化の比重が大きい傾向があります。

### ヘルプデスクの経験だけで、社内SEの求人に応募できますか？
応募できる求人はあります。必須要件が「いずれか」で書かれ、ヘルプデスクや端末の管理の経験が含まれている求人です。アカウントの管理や手順書の整備など、問い合わせ対応以外に担ってきた仕事も伝えると、範囲の重なりが伝わりやすくなります（[情報システムのヘルプデスク求人の読み方](/guide/corporate-it-helpdesk/)）。

### 社内SEの求人でも、プログラミングをしますか？
求人によります。業務アプリケーションを内製する求人や、業務の自動化を進める求人ではプログラミングの機会があります。外部の会社に開発を依頼する形の求人では、要件の整理や確認が中心で、コードを書く機会は少なめです。仕事内容に開発言語やローコードツールの記載があるかを確かめてください。
