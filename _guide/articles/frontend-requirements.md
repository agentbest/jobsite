フロントエンドエンジニアの求人の必須要件は、開発経験の年数とフレームワークの経験に加えて、TypeScript・チームでの開発・画面の設計の経験の組み合わせで書かれることが多いです。ReactとVue.jsのようなフレームワークの違いは「いずれか」として扱う求人が多く、差を埋めやすい条件です。一方で、実装だけでなく設計を担った経験や、フルスタック型の求人で求められるサーバー側の経験は、伝え方によって評価が変わります。

## フロントエンドの必須要件によく出る項目

フロントエンドの求人の必須要件は、おおむね次の項目の組み合わせです。

| 項目 | 書き方の例 | 見られていること |
|---|---|---|
| 年数 | 「Webフロントエンド開発の実務経験◯年以上」「Webアプリケーション開発◯年以上」 | 画面側に限った経験か、Web開発全体の経験か |
| フレームワーク | 「React、Vue.jsいずれかでの開発経験」「SPAの構築・運用経験」 | 今の画面の作り方にすぐ入れるか |
| 言語 | 「TypeScriptを用いた開発経験を含む」 | 型を使って、壊れにくいコードを書いてきたか |
| 基礎知識 | 「HTTP・DNSなどネットワークの基礎」「セキュリティの基礎」 | ブラウザの外で何が起きているかを理解しているか |
| チーム開発 | 「Gitを用いたチーム開発」「Pull Requestベースの開発」 | レビューを通じて共同でコードを育ててきたか |
| 設計 | 「状態管理・コンポーネント設計・API連携の方針」 | 画面が増えても保ちやすい構造を考えてきたか |
| サーバー側 | 「フロントエンド／バックエンド双方の開発経験」 | フルスタック型の求人で、API側まで担えるか |

フロントエンドの求人では、基礎知識やチーム開発の項目が、年数やフレームワークと同じ重さで並ぶことがあります。画面の実装だけでなく、通信やセキュリティの仕組みを理解しているかも見られていると考えるとよいでしょう。

## 年数の書かれ方：フロントだけか、Web開発全体か

年数の条件は、どの範囲の経験を数えるかで意味が変わります。

- 「Webフロントエンド開発◯年以上（うちTypeScript◯年）」……画面側の経験を、言語まで分けて見ている
- 「Webアプリケーション開発◯年以上」……画面とサーバー側を合わせた経験で見ている
- 「Web開発の経験◯年以上（言語不問）」……経験の長さより、開発の流れに慣れているかを見ている

サーバー側の開発からフロントエンドへ移りたい場合は、「Webアプリケーション開発」の年数で数える求人のほうが届きやすくなります。反対に、フロントエンドの経験の中で「うちTypeScript◯年」のような内訳がある求人は、内訳まで満たしているかを確かめましょう。

## フレームワークの条件の読み方

フレームワークは、求人によって厳しさがはっきり分かれる条件です。

- **「React、Vue.jsいずれか」「それに類するフレームワーク」**：コンポーネントで画面を組み立てる考え方に慣れていれば、どちらの経験でもよいという書き方
- **「Reactでの実務経験◯年以上」**：特定のフレームワークを指定している。採用後すぐに中心メンバーとして入ってほしい求人に多い
- **「モダンなフロントエンドフレームワーク」**：特定の名前を出さず、今の主流の作り方の経験を求めている

「いずれか」の求人は、ReactとVue.jsの違いを入社後に埋められると考えています。特定のフレームワークの年数が必須の求人でも、歓迎要件に別のフレームワークの経験が並んでいれば、考え方の近さを評価してもらえることがあります。フレームワークの書かれ方は[フロントエンドの求人のフレームワークの読み方](/guide/frontend-frameworks/)でも扱っています。

:::view
フロントエンドの求人では、必須要件にReactと書かれていても、Vue.jsでの設計の経験を同じように見る会社もあれば、指定のフレームワークの実務経験を重く見る会社もあります。求人をご紹介していると、この線の引き方は求人票の文面だけでは分からないことが多いです。フレームワークの違いをどこまで許容するかは、ご質問いただければ企業に確認できます。
:::

## TypeScriptが必須に入っている求人

フロントエンドの求人では、TypeScriptの経験を必須に置くものがよく見られます。見られているのは、型を書けることより、型を使ってデータの形を決め、変更に強いコードを書いてきたかどうかです。

JavaScriptでの開発が中心だった場合は、既存のコードに型を足した経験、個人の開発でTypeScriptを使った経験など、触れた範囲を正直に書きます。「TypeScriptの経験を含む」と年数の中に組み込まれている求人は、実務の経験を前提にしていることが多いので、差がある場合は応募前に確かめておくと安心です。TypeScriptが必須の求人の読み方は[TypeScript必須の求人の読み方](/guide/frontend-typescript/)をご覧ください。

## 歓迎要件から分かる、そのチームの課題

歓迎要件には、そのチームがいま取り組んでいることが表れます。

- **SSR・Next.jsの経験**……初期表示の速さや、検索エンジンへの対応を改善したい
- **パフォーマンス改善（Core Web Vitalsなど）の経験**……表示の速さを数字で管理している、または管理しようとしている
- **アクセシビリティに配慮した開発**……誰でも使える画面を、品質の基準として持とうとしている
- **デザインシステム・UIコンポーネントライブラリの設計**……複数の画面やプロダクトで部品を共通化している
- **E2Eテスト・ユニットテストの経験**……画面の変更で不具合を出さない仕組みを整えている
- **GraphQL・BFFの設計、フロントとバックエンドの分離**……画面とサーバーの境界を作り直している
- **大量データの表示、リアルタイム通信の経験**……業務用の複雑な画面を扱っている

自分の経験と重なる項目があれば、面接で一番話しやすい材料になります。性能や品質の経験の書かれ方は[フロントエンドの求人に出る性能・品質の経験](/guide/frontend-performance/)で扱っています。

## シニア・リードの求人の必須要件

シニアやテックリードの求人になると、必須要件の重心が実装から判断へ移ります。

- 「技術選定・アーキテクチャ設計の経験」……どの技術を、なぜ選んだかを説明できる
- 「技術やプロダクト、開発プロセスの課題解決をリードした経験」……チームの進め方を変えた経験
- 「技術的な選択肢を非エンジニアに説明した経験」……デザイナーや事業側の人と合意を取ってきた
- 「コードレビューや品質の維持・向上の経験」……ほかの人のコードに責任を持ってきた

この層の求人では、年数より、判断した場面を具体的に話せるかが見られます。リード候補の求人で求められることは[フロントエンドのリード候補の求人で求められること](/guide/frontend-lead/)をご覧ください。

## 必須要件を満たしていないときの考え方

届かない条件があるとき、フロントエンドの求人では次の4つの差に分けて考えると判断しやすくなります。

1. **フレームワークの差（Vue.jsの経験でReactの求人を見ている、など）**：「いずれか」「類する」と書かれていれば応募してよいケースが多いです。コンポーネントの分け方や状態管理の考え方を説明できれば、違いは埋めやすいと見てもらえます
2. **言語の差（JavaScript中心で、TypeScriptの実務経験が少ない）**：触れた範囲を正直に書き、学び方を話せるようにします。年数の内訳まで指定されている求人は通りにくくなります
3. **設計の差（実装を担当してきたが、設計を決めた経験が少ない）**：画面の部品を共通化した、ディレクトリ構成を見直した、といった小さな設計の経験も書けます。シニア・リードの求人では差が大きくなります
4. **サーバー側の差（フルスタック型の求人で、API開発の経験がない）**：「双方の開発経験」が必須なら通りにくくなります。「バックエンドの経験は歓迎」なら、画面側の経験で応募できます

1と2は、学び方と考え方の説明で補える余地が大きい差です。3と4は、求人がどの役割を求めているかを確かめたうえで、応募先を選ぶのがおすすめです。

## マークアップやWebサイト構築の経験から応募するとき

HTML・CSSでのコーディングや、CMSを使ったWebサイトの構築が中心だった場合、Webアプリケーションの求人の必須要件とは重心が違います。Webサイトの構築を扱う求人では、その経験がそのまま生きます。アプリケーションの求人を目指す場合は、JavaScriptで画面の動きを作った経験、フレームワークで作った個人の成果物などを用意し、どこまで経験しているかを具体的に示すと判断してもらいやすくなります。

:::view
フロントエンドの求人は、選考でコードや成果物を見る会社もあり、書類の経歴だけでは伝わりにくい設計の考え方が評価につながることがあります。当社からの応募は当社への申し込み（無料）で、当社から企業へ推薦する形で選考が進みます。フレームワークや担当範囲の差があっても、サイトに載せていない非公開の求人を含めて、経験に近い求人を個別にお探しできます。
:::

フロントエンドエンジニアの求人は[エンジニアの求人一覧](/jobs/engineer/)から探せます。仕事内容の欄の読み方は[フロントエンドエンジニアの求人票の読み方](/guide/frontend-posting/)をご覧ください。

## よくある質問

### Vue.jsの経験しかありませんが、Reactの求人に応募してもよいですか？
必須要件が「React、Vue.jsいずれか」や「類するフレームワーク」なら、応募してよいケースが多いです。Reactの実務年数が必須に書かれている場合は通りにくくなります。コンポーネント設計や状態管理の考え方を説明できるようにしておくと、違いは埋めやすいと見てもらえます。

### フルスタックの求人に、フロントエンドの経験だけで応募できますか？
必須要件しだいです。「フロントエンド／バックエンド双方の開発経験」が必須なら、サーバー側の経験がないと通りにくくなります。サーバー側が歓迎要件にとどまっていれば、画面側の経験で応募できます。

### 個人開発の経験は、必須要件の経験として見てもらえますか？
多くの求人では、必須要件の年数は実務の経験で数えられます。ただし、使ったことのない技術に触れていることを示す材料として、個人開発の成果物は評価されることがあります。「個人開発でも可」と書かれた歓迎要件があれば、そのまま話題にできます。
