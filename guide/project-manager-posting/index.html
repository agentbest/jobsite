プロジェクトマネージャー（PM）の求人票は、「どの役割のPMなのか」「受注側・発注側・自社サービスのどの立場か」「規模と責任の範囲はどこまでか」の3点で読むと、求人ごとの違いが見えてきます。同じ「PM」という職種名でも、予算や損益まで責任を持つ仕事から、大きなプロジェクトの一部をまとめる仕事、PMを支える管理業務まで幅があります。

求人の「PM」が指す役割を見分ける

PMの求人には、職種名やポジション名にさまざまな呼び方が出てきます。中身はおおむね次のように分かれます。

呼び方求人票によく出る書き方中心になる仕事
PM（プロジェクトマネージャー）「コスト・納期・品質を一貫して管理」「予実管理」プロジェクト全体の計画と責任。顧客や社内の上位層との調整
PL（プロジェクトリーダー）「チームのとりまとめ」「PMの補佐」担当チームの進捗・品質の管理。自分も設計や実装を担うことが多い
PMO「進捗・課題・リスクの管理」「会議体の運営」「ステークホルダー管理」PMを支える管理業務。計画の見える化や報告のとりまとめ
PM候補・PL/PM候補「開発を担当しながら、将来的にPL/PMへ」当面は開発者として参加し、段階的にマネジメントを任される
プレイングマネージャー「プロジェクトの推進を自ら先頭に立って」「手を動かすことも可能」管理と技術の両方を担う。少人数のチームに多い
開発ディレクター・PdM寄り「顧客の要望をヒアリングし、何を作るかを決める」企画や要件の整理が中心で、開発の管理も兼ねる

ポジション名に「PM」とあっても、仕事内容を読むと「大規模案件のPMを補佐する役割」のようにPLやサブPMの役割だった、ということもあります。職種名だけで判断せず、仕事内容の主語と動詞（誰が、何を決めるのか）を読み取りましょう。PMとPMOの違いはPMとPMOの求人の違いで詳しく扱っています。

どちら側のPMか：受注側・発注側・自社サービス

PMの仕事は、会社がプロジェクトのどちら側にいるかで大きく変わります。

  • 受注側（SIer・受託開発）：顧客から開発を請け負う側のPM。見積もり、要員の計画、コスト・納期・品質の管理、顧客への報告が中心です。「受注後、キックオフからPMとして管理」「営業部門と連携したプロジェクト拡大」といった書き方が出てきます
  • 発注側（事業会社・ユーザー企業）：自社のシステムを外部に発注する側のPM。「ベンダーコントロール」「IT投資予算の策定」「社内の利用部門との調整」が中心です。自分で作るより、外部の開発会社を選び、管理し、成果物を確かめる仕事になります
  • 自社サービス：自社のプロダクトを開発するチームのPM。「アジャイル」「スクラム」と並んで書かれることが多く、期限と範囲を固定した計画より、優先順位を見直しながら進める力が求められます
  • PMO支援・客先常駐：顧客のプロジェクトにPMOとして参加する形。「大手SIerのプロジェクトに参画」「関係各所との調整・折衝」と書かれます。働く場所や指示を受ける相手が顧客側になることがあります

同じ「予算管理」という言葉でも、受注側では「自社の利益を守るための原価管理」、発注側では「会社のIT投資を計画どおりに使うための管理」と意味が違います。立場ごとの違いはSIerとユーザー企業のPMの求人の違いもご覧ください。

エージェントベストの見解

PMの求人は、同じ職種名でも担当範囲や責任の重さが会社ごとにかなり違います。求人をご紹介していると、PMと書かれていても実際にはPLに近い役割だったり、反対にPM候補と書かれていても入社後すぐに小さなプロジェクトを任されたりするケースを見かけます。配属や役割など求人票に書かれていないことは、ご質問いただければ当社から企業に確認できます。

規模と責任の書かれ方

PMの求人では、プロジェクトの規模が数字で書かれることがあります。規模を表す書き方には、次のような種類があります。

  • 人数：「チームメンバー5〜10名」「20名以上のプロジェクト」
  • 期間：「プロジェクト期間が半年程度」「有期プロジェクト」
  • 金額：「案件規模◯千万円以上」「予算規模◯億円以上」
  • 工数：「人月での開発リソース計画」「工数・予算の管理」
  • 組織：「◯名以上の技術者組織の運営」

数字が書かれていれば、自分が経験してきたプロジェクトと比べやすくなります。比べるときは、人数だけでなく、外部の会社が何社関わっていたか、顧客の窓口がいくつあったかなど、調整の複雑さも思い出しておくと、面接で具体的に話せます。

責任の範囲は、動詞から読み取れます。「予実管理」「損益」「見積書作成・費用管理」が仕事内容にあれば、お金の責任まで持つ立場です。「進捗管理」「課題管理」だけなら、計画どおりに進めることが中心で、予算の決定には関わらないこともあります。規模の書かれ方の詳しい読み方はPMの求人に書かれる規模・予算の読み方で扱っています。

管理する対象は何か

PMの仕事というと、スコープ（範囲）・コスト・品質・納期の管理が中心ですが、求人によってはそれ以外の役割が加わります。

  • 営業・提案：「プリセールス」「案件創出のための提案」「拡販活動」……受注前から関わる
  • 人材育成・組織運営：「プロジェクトや社内グループの人材育成」「チームメンバーの評価・育成」……人の管理も担う
  • 技術の判断：「技術選定」「アーキテクチャの検討」……技術面のリードも期待されている
  • 業務改革：「業務課題の整理、改善計画の立案」「業務プロセス改革」……システムより業務の変え方が中心

こうした役割が仕事内容にあると、PMとしての管理に加えて、どこに時間を使うことになるかが変わります。自分が伸ばしたい方向と合うかを確かめましょう。

職種分類の幅に注意する

「プロジェクトマネージャー（Web・オープン系）」に分類された求人の中にも、システム開発以外のPMの求人が含まれていることがあります。コンタクトセンターの運営、物流設備の導入、建設やプラントの工事管理など、プロジェクトの管理という点は共通でも、必要な経験はまったく違います。中には、ソフトウェア開発のPM経験は対象外と明記している求人もあります。

ITのPMとして探している場合は、仕事内容に「システム開発」「要件定義」「ベンダー」などの言葉があるかを確認すると、見分けやすくなります。

働き方の欄で見ておくこと

PMの求人では、働く場所や働き方にも特徴があります。

  • 常駐の有無：PMOや受注側のPMでは、顧客の事業所で働くことがある。リモートの可否も顧客の方針で変わることが多い
  • 出張：拠点が複数ある顧客や、設備の導入を伴うプロジェクトでは出張が発生する
  • 変更の範囲：「（変更の範囲）会社の定める業務」とある場合、PMから営業や組織運営へ役割が広がる可能性もある（業務内容の「変更の範囲」の読み方）
  • 管理職の扱い：「マネージャー」の職位で採用される場合、残業代の扱いが変わることがある（「管理職」の求人と残業代）

応募前に確かめたいこと

PMの求人で、求人票だけでは分かりにくく、入社後の働き方に関わる項目をまとめます。

よくある質問

PL（プロジェクトリーダー）の経験しかありませんが、PMの求人を見てもよいですか？

見てよいです。PMの求人の中には、PL経験を前提にPMへ段階的に移ることを想定したものもあります。仕事内容の役割（予算の責任があるか、何人のチームか）と自分の経験の差を確かめたうえで、応募するかを判断してください。

PMOの求人は、PMになるための経験になりますか？

計画づくりやリスク管理、報告のとりまとめなど、PMに必要な力を近くで身につけられる面があります。ただ、PMOは意思決定を支える役割なので、自分で決めて責任を持つ経験は積みにくいこともあります。将来PMを目指すなら、PMOからPMへ移った例があるかを聞いてみてください。

技術の経験が少なくても、ITのPMの求人に応募できますか？

求人によります。必須要件に「システム開発の経験◯年以上」とある求人は、技術の経験を前提にしています。一方、発注側や業務改革寄りのPMでは、業務の理解や調整の経験が重視されることもあります。必須要件で技術の経験をどこまで求めているかを確かめてください。

PMの募集背景は、どの種類の人手不足を埋めたいかを示します。案件増なら既存の進め方で早く案件を持つこと、上流人材の不足なら提案や見積もりから入ること、組織変革なら案件に加えて体制づくりを担うことが中心です。読み方と確認点を整理しました。

PMの仕事の範囲は、受け持つ工程、自分で手を動かす割合、1案件か複数案件か、人の管理をどこまで持つかで求人ごとに違います。範囲の広い書き方と狭い書き方、自分の経験との照らし合わせ方をまとめました。
