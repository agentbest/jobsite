プロジェクトマネージャー（PM）の仕事の範囲は、「どの工程からどの工程までを持つか」「自分で手を動かす割合」「1つの案件を持つか複数を束ねるか」「人と組織の管理をどこまで持つか」の4つで、求人ごとに大きく違います。同じPMの求人でも、提案から運用の引き継ぎまで1人で通す仕事もあれば、上流の工程と管理に絞り、開発は別のチームに任せる仕事もあります。求人票の仕事内容を4つの軸で読み分けると、入社後の1日の使い方が想像しやすくなります。

工程の幅：提案・見積もりから運用の引き継ぎまで

PMが持つ工程は、求人によって始まりと終わりが違います。仕事内容に出てくる言葉を、次の段階に当てはめてみます。

  1. 受注前：事前調査、見積もり、提案、RFP（提案依頼書）の準備
  2. 上流：要件のヒアリング、要件定義、技術選定、方式設計
  3. 開発・テスト：設計、実装、テストの管理
  4. 導入：現地での設置や調整、立ち会い、利用者への引き渡し
  5. 運用への引き継ぎ：検収、運用チームへの引き継ぎ、保守

営業部門と組んで提案から入り、受注後もそのまま設計から導入まで担当する、と書かれた求人は、1から4までを通して持つ仕事です。反対に、開発やテストは別の担当者が行うと書かれた求人では、PMは上流の工程と管理に重心を置きます。機器の導入を伴う求人では、据え付けや工事の現地立ち会いまで範囲に入ることがあります。

始まりが受注前にある求人では、見積もりの精度や提案の内容にもPMが責任を持ちます。終わりが運用の引き継ぎにある求人では、リリース後の安定稼働を見届けるところまでが仕事です。

自分で手を動かす割合

PMの求人は、自分で設計や実装をどのくらい担うかでも分かれます。

  • プレイング型：「開発業務（要件定義〜テスト）」と「進捗管理・メンバーの育成」が並んで書かれる。少人数のチームのリーダーに多く見られます
  • 技術リード型：「技術選定」「コードレビュー」「開発フローの整備」が中心。テクニカルディレクターやリードエンジニアの名前で募集されることもあります
  • 管理専任型：個別の案件には入らず、部門の全案件の品質・コスト・納期とリスクをまとめて見る、と明記する求人もあります

プレイング型は、管理の経験と技術の経験を同時に積める一方、どちらに時間を取られるかは案件の状況で変わります。管理専任型は、自分で手を動かさない分、各案件のリーダーを通じて進める力が問われます。技術リード型は、管理よりも技術の判断に重心があり、プロジェクトの立ち上げ時に開発の進め方を整えて、軌道に乗ったら次の案件へ移る、という関わり方をする求人もあります。どの型かは、仕事内容の箇条書きで「管理」の言葉と「開発」の言葉のどちらが多いかを見ると見当がつきます。

1つの案件か、複数を束ねるか

同時に持つ案件の数も、範囲を大きく左右します。

  • 大きな案件を1つ：数年にわたる長期の案件を担当する求人もあります。1つの顧客と深く関わります
  • 大きな案件と小さな案件を並行：主担当の案件を持ちながら、小規模の案件をいくつか見る形です
  • 部門の案件を横断：部門全体の案件の進み方を見て、遅れそうな案件を早めに見つけ、立て直す役割です
  • PMOとして支える：PMの方針をチームに伝え、進捗や課題、コストの管理を担います

複数の案件を束ねる求人では、必須要件に「複数のプロジェクトを同時に管理した経験」と書かれることがよくあります。PMとPMOの違いはPMとPMOの求人の違いで扱っています。

エージェントベストの見解

PMの求人をご紹介していると、1つの求人票に「メンバー」「PL」「スペシャリスト」など複数の役割の段階が併記されていることをよく見かけます。どの段階で採用されるかで、持つ工程も管理する人数も変わります。どの段階を想定した選考なのか、最初にどの案件を担当するのかは、ご質問いただければ企業に確認できます。

人と組織の管理をどこまで持つか

人の管理も、求人によって深さが違います。仕事内容から次の言葉を拾います。

  • チームの運営：タスクの割り振り、進捗の確認、メンバーのフォロー
  • アサインと稼働の管理：社員や業務委託、協力会社の要員の配置と稼働の管理
  • 育成と評価：1on1、指導、評価への関与
  • 採用：新しいメンバーの採用への参加
  • 仕組みづくり：管理ツールの運用ルールの整備、開発の進め方の標準化
  • 組織と収益：部門の運営、営業活動、売上の責任。上位の職位の求人で見られます

管理する人数は「5〜8名程度」のように書かれることもあれば、書かれないこともあります。協力会社のメンバーを含む人数なのか、社員だけの人数なのかで意味が変わるため、数字がある場合は内訳も確かめます。チームの組み方は配属先とチーム体制の読み方、職位ごとの違いはポジション別の違いで扱っています。

扱う領域で変わる範囲

PMの職種に分類される求人には、システム開発以外の領域を扱うものも含まれます。領域によって、範囲に入る仕事が変わります。

  • インフラ構築：上流の設計から、機材やソフトウェアの選定、見積もり、現地での設置作業のとりまとめまでを持つことがあります
  • テスト・品質保証：テストの計画、設計、実行、結果の分析と報告をまとめるリーダーの役割です。テストの自動化の検討まで範囲に入る求人もあります
  • 業務の自動化：顧客の業務の聞き取りから、ツールの選定、要件定義、開発、保守までを通して担う求人があります
  • マーケティングの案件：顧客の課題の整理と戦略づくりから、社内外のチームを動かした施策の実行、成果の確認までを担います

同じ「PM」でも、インフラの案件では機器や工事の段取り、品質保証の案件ではテストの設計、マーケティングの案件では顧客の事業の数字が仕事の中心になります。自分の経験がどの領域のものかを確かめ、求人の領域と合うかを見ておきます。

範囲の違いを比べる表

4つの軸について、範囲が狭めの書き方と広めの書き方を並べると次のようになります。

軸狭めの書き方広めの書き方
工程「上流工程を担当」「開発は委託」「提案から導入まで一貫して」「運用への引き継ぎまで」
手を動かす割合「管理に専念」「個別案件には入らない」「開発業務も担当」「プレイングマネージャー」
案件数「1プロジェクトを担当」「部全体の案件を管理」「複数案件を同時に」
人と組織「チームのとりまとめ」「アサイン・育成・採用」「組織運営・収益責任」

どちらが良いということではありません。広い範囲は経験の幅が増える一方で、1つの工程を深める時間は取りにくくなります。自分が次に伸ばしたいところに合わせて選ぶことが大切です。

範囲が読み取りにくい書き方

求人票には、範囲をあえて決めていない書き方もあります。

  • 「プロジェクトにもよりますが」：案件ごとに範囲が変わります。最初の案件の内容を聞いておきます
  • 「経験に応じて」：入社時の範囲は選考で決まります。どの段階から始めるかを確かめます
  • 「案件の切り出し後は」：まずは開発やチームづくりから入り、後からPMの範囲に広がる流れです
  • 「（変更の範囲）会社の定める業務」：将来、PM以外の仕事に移る可能性があります。読み方は業務内容の「変更の範囲」の読み方をご覧ください

範囲は入社後に段階的に広がることもあります。リーダー経験がなくても少しずつ役割を広げる、将来はチームのリーダーやマネジメントを任せる、といった書き方の求人は、最初は狭い範囲から始め、経験に合わせて工程や人数を増やしていく前提です。反対に、入社直後から部門の案件をまとめて見る求人もあります。最初の半年ほどで任される範囲と、その後に広がる範囲を分けて聞いておくと、立ち上がりの計画を立てやすくなります。

自分の経験と照らし合わせる

応募を考えるときは、4つの軸ごとに自分の経験を書き出してみます。どの工程を通して持ったか、自分で手を動かしていた割合、同時に持った案件の数、管理した人数とその内訳です。求人の範囲と比べて、重なる軸と足りない軸が分かれば、職務経歴書で強調する点と、面接で補う点が決まります。

面接では、範囲について次のような質問をしておくと、入社後のずれを防げます。

  1. 最初に担当する案件の工程と期間、チームの人数
  2. 自分で設計や実装を担う場面がどのくらいあるか
  3. 同時に持つ案件の数と、優先順位を決める人
  4. メンバーの評価や採用に関わるかどうかSEからPMを目指す場合の見せ方はSEからPMの求人に応募するときの経験の見せ方、必須要件の読み方はプロジェクトマネージャーの求人の必須要件・歓迎要件で扱っています。

よくある質問

プレイングマネージャーの経験は、PMの経験として見てもらえますか？

見てもらえることが多いです。ただ、管理に使った時間と、自分で開発した時間の割合は人によって違うため、職務経歴書では管理した人数や工程、判断した内容を具体的に書くと伝わりやすくなります。

複数案件を同時に管理した経験がありません。横断型のPMの求人に応募できますか？

必須要件に複数案件の管理経験が書かれていれば、その経験を前提にした求人です。1つの案件の中で複数のチームや協力会社をまとめた経験があれば、近い経験として説明できる場合があります。必須か歓迎かを先に確かめてください。

受注前の提案や見積もりに関わったことがなくても、提案から入るPMの求人に応募できますか？

応募できる求人もあります。提案から入る求人では、営業部門と組んで進める形が多く、要件のヒアリングや工数の見積もりの経験が生きます。提案の段階でPMがどこまで責任を持つのかは、面接で確かめてください。
