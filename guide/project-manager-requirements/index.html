プロジェクトマネージャーの求人の必須要件・歓迎要件｜満たしていないときの考え方

プロジェクトマネージャー（PM）の求人の必須要件は、役職名そのものより、「何を管理してきたか」と「その土台になる開発・顧客折衝の経験」の2つで書かれることが多いです。「PM・PLいずれかの経験」「役職名は不問」と書く求人も多く、PL（プロジェクトリーダー）やチームリーダーの経験でも届く求人は少なくありません。届かない条件があるときは、役割・規模・技術・領域のどれの差なのかを分けて考えると、応募するかどうかを判断しやすくなります。

PMの必須要件によく出る4つの型

PMの求人の必須要件は、おおむね次の4つの型の組み合わせです。

型書き方の例見られていること
役割の経験「PM・PLいずれかの経験」「リーダー／サブリーダー経験」「チームリーダーの経験」人とタスクをまとめる立場に立ったことがあるか
管理の実務「WBSの作成」「見積作成（機能・工数・金額）」「進捗・課題管理、顧客への報告」計画を立て、数字で管理し、報告してきたか
技術の土台「開発経験◯年以上」「一人称で開発できる」「基本設計・詳細設計の経験」開発の中身を理解したうえで判断できるか
対外の経験「顧客との要件定義」「顧客折衝」「関係者と合意形成しながら進める力」社外や他部署と調整し、決めるべきことを決めてきたか

求人によって、どの型を重く見るかが違います。受託開発の求人では「技術の土台」と「管理の実務」が並びやすく、事業会社や自社サービスの求人では「対外の経験」や合意形成の力が前に出やすい傾向があります。仕事内容の欄で役割や立場を読む方法はプロジェクトマネージャーの求人票の読み方で扱っています。

「役職名は不問」と書かれた求人の読み方

PMの求人には、「役職名は問いません」「規模は問いません」と添えたうえで、実務の中身を並べるものがあります。この場合に見られているのは、肩書きではなく、実際にやってきたことです。

  • タスクを分けてメンバーに割り振った
  • 進行を管理し、遅れが出たときに計画を立て直した
  • 設計やコードのレビューをして、品質に責任を持った
  • 顧客や他部署との打ち合わせで、決めるべきことを決めた

正式な役職がなくても、こうした実務を担っていれば、書類でそのまま書けます。逆に「PM」という肩書きがあっても、実際には進捗の取りまとめだけだった場合は、求人が求める中身とずれていないかを確かめておきましょう。

「PM経験」と「開発経験」が並んでいる求人

必須要件が「プロジェクト・チームのマネジメント経験◯年以上、または開発経験◯年以上」のように、2つの入口を並べている求人があります。マネジメントの経験がある人はそのまま、開発の経験が長い人は開発の側から入れる、という書き方です。

開発の入口から応募する場合は、入社後にマネジメントへ移ることが前提になっていることが多いです。リーダーとして後輩を見た経験、見積もりやスケジュールの作成を手伝った経験など、マネジメントに近い経験を添えておくと、移る道筋を描いてもらいやすくなります。SEからPMを目指すときの経験の見せ方はSEからPMの求人に応募するときの経験の見せ方をご覧ください。

エージェントベストの見解

PMの求人では、必須要件に「PM経験」と書かれていても、PLやチームリーダーとして計画と進捗に責任を持ってきた経験を同じように見る会社もあれば、予算や損益まで持った経験に限る会社もあります。求人をご紹介していると、この線の引き方は求人票の文面だけでは読み取りにくいことが多いです。どこまでの経験を「PM経験」と見るかは、ご質問いただければ企業に確認できます。

歓迎要件から分かる、求められる次の役割

歓迎要件には、PMとして入社した後に広がる役割が表れます。

  • 複数の関係者が関わるプロジェクトの経験（金融・公共など）……利害の違う関係者が多い案件を任せたい
  • アジャイル・スクラムの経験……計画を固定するより、優先順位を見直しながら進めるチーム
  • プリセールス・提案の経験……受注前の提案や見積もりからPMが関わる
  • 後輩や新人の育成経験……プロジェクトだけでなく、人を育てる役割も期待されている
  • 特定の業界・製品の知見（製造・金融・SaaS製品など）……業務を理解して要件を整理できる人を求めている
  • PMPなどの資格……体系立てた管理の知識を持っている人への加点

資格は多くの求人で歓迎要件に置かれていて、資格がないことで応募できないケースは多くありません。資格の書かれ方はPMの求人に書かれる資格の読み方で扱っています。アジャイルの求人の読み方はアジャイル開発のPMの求人の読み方もご覧ください。

PMOの求人の要件は少し性格が違う

PMOの求人の必須要件には、「PMOまたはプロジェクトマネジメントの経験」に加えて、開発の経験か、自分のチームの外をまとめた経験のどちらかを求めるものがあります。プロジェクトを横から支える立場なので、全体を見渡す力と、開発の現場の事情を理解していることの両方が見られます。

上流の工程のうち一部だけを経験していれば応募できる、と書く求人もあります。PMを目指す途中でPMOの求人を見る場合は、PMとPMOの役割の違いを理解したうえで選ぶのがおすすめです。違いはPMとPMOの求人の違いで扱っています。

「推進力」「判断力」と書かれた条件の読み方

PMの求人には、経験の年数ではなく、仕事の進め方を必須要件に置くものもあります。

  • 「関係者と合意を取りながら前に進める推進力」……意見の違う相手の間に立ち、決めるべきことを決めて進めた経験
  • 「根拠を持って優先順位を付け、判断できる」……やることを絞り、やらないことを決めた経験
  • 「課題に対して自律的に考え、計画を立てて実行できる」……指示を待たず、自分で計画を作って動かした経験
  • 「品質・スケジュール・範囲を意識した進行管理」……どれかを守るために、ほかの何を調整したかを説明できること

こうした条件は、書類では伝わりにくく、面接で具体的な場面として聞かれます。条件の言葉をそのまま使うより、「どんな状況で、何を比べ、何を選び、結果どうなったか」を話せるようにしておくと伝わります。

必須要件を満たしていないときの考え方

届かない条件があるとき、PMの求人では次の4つの差に分けて考えます。

  1. 役割の差（PLやリーダーまでで、PMの経験がない）：「PM・PLいずれか」「PM候補」と書かれた求人なら、そのまま応募できます。「PMとして予算・損益の責任を持った経験」が必須なら差は大きく、管理した範囲を正確に書いたうえで判断してもらう形になります
  2. 規模の差（小さなチームの経験で、大規模案件の求人を見ている）：人数の差より、関係者の多さや、外部の会社との調整の有無のほうが重く見られることがあります。少人数でも、複数の会社や部署の間に立った経験があれば伝えられます
  3. 技術の差（開発の経験が浅い、またはない）：受託開発のPMで「開発経験◯年以上」が必須なら通りにくくなります。発注側や業務改革寄りのPMでは、業務の理解や調整の経験が重く見られることもあるので、必須要件で技術の経験をどこまで求めているかを先に確かめます
  4. 領域の差（Web制作のディレクター、インフラのリーダーなど）：計画・進捗・品質を管理してきた経験は共通して使えます。ただし、求人の扱うシステムや業界の知識が必須に入っていれば、その部分は別に考える必要があります

1と2は、経験の書き方で届く余地が大きい差です。3と4は、求人が技術や業界の知識をどこまで前提にしているかで判断が分かれます。

職務経歴書で求人と照らし合わせやすくする

PMの経験は、肩書きだけでは中身が伝わりません。必須要件と照らし合わせてもらうために、プロジェクトごとに次の項目を書いておくと、読み手が判断しやすくなります。

項目書いておきたいこと
立場受注側か発注側か、元請けか二次請けか
体制自分の配下の人数、関わった社外の会社や部署
役割PM・PL・サブリーダーのどれか、誰に報告していたか
管理した対象スケジュール・品質・コスト・要員・ベンダーのどこまでか
使った手法WBS、見積もり、課題管理表、アジャイルの進め方など
判断した場面遅れや仕様変更が起きたとき、何をどう決めたか

数字で書ける部分（人数、期間など）は、自分の経験の実際の値で書きます。判断した場面は、面接で深く聞かれやすいところなので、1つか2つ具体的に話せるようにしておくと安心です。

エージェントベストの見解

PMの求人は、PL経験からの応募を歓迎する求人と、PMとしての実績を強く求める求人がはっきり分かれる職種です。当社からの応募は当社への申し込み（無料）で、当社から企業へ推薦する形で選考が進みます。これまで担ってきた役割と規模を伺ったうえで、サイトに載せていない非公開の求人も含めて、届きやすい求人を個別にお探しできます。

プロジェクトマネージャーの求人はプロジェクト管理の求人一覧で探せます。求人の動向はプロジェクト管理の求人・年収動向やページ下の掲載データもご覧ください。

よくある質問

サブリーダーの経験しかありませんが、PMの求人に応募できますか？

「リーダー／サブリーダー経験」や「PM候補」と書かれた求人なら応募できます。PMとしての実績が必須の求人は通りにくいですが、タスクの割り振りや進捗の管理を担った経験があれば、その範囲を具体的に書いて判断してもらう形になります。

PMPなどの資格がないと不利になりますか？

多くの求人では、資格は歓迎要件に置かれています。資格がないことで応募できないケースは多くありません。資格より、実際に計画を立てて管理してきた経験のほうが重く見られるのが一般的です。

エンジニア経験がなくても、ITのPMの求人に応募できますか？

必須要件しだいです。「開発経験◯年以上」がある求人は技術の経験を前提にしています。発注側のPMや業務改革寄りの求人では、業務の理解や関係者との調整の経験が重く見られることもあるので、技術の経験をどこまで求めているかを確かめてください。
