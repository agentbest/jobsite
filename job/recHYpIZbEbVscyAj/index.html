仕事内容

■仕事概要
国内最大級のWeb3ウォレット「HashPort Wallet」（EXPO2025デジタルウォレットの後継、100万ユーザー）を運営してきたHashPortが、その基盤を企業向けに開くAPI基盤「HashPort Studio」（ウォレット基盤「Wallet Core」、ステーブルコイン決済基盤「Payment Core」）の開発プロジェクト責任者です。要件確定・外部開発会社の管理・リリース・運用保守までを一気通貫で担い、テックリードと企画責任者の間に立って、開発側の視点で事業側にも気を配りながらプロジェクトを完遂していただきます。最初の決済案件は大手小売チェーンの店頭決済です。

■仕事の詳細

  • Wallet Core / Payment Core系案件（店頭決済、企業向けウォレット・決済基盤の提供、事業者向け管理画面）のスコープ・スケジュール・品質・コスト管理
  • 外部開発会社2社の管理：仕様の確定と伝達、見積もりの査定、進捗・課題管理、成果物のレビューと検収
  • 要件定義・API仕様・受入テストのレビュー、顧客側システムとの接続仕様の調整
  • リリース管理：顧客への影響説明、手順書とリハーサル、本番適用と事後報告
  • 運用保守：監視・障害対応・問い合わせ導線・変更管理の設計と、運用開始後の主担当
  • 法務・コンプライアンス論点（ノンカストディ、資金決済法上の位置づけなど）を法務担当と整理し、システム要件に落とし込み
  • 引合い時の技術面でのプリセールス協力（実現可否・概算工数・リスクの整理）

【配属・体制】

  • プロダクト開発グループ所属。グループマネージャーが統括するPMチーム（現在2名）に3人目として参加
  • 決済基盤本体の開発は外部開発会社2社と社内チームの3者並行
  • 技術判断の最終責任はシステム責任者（テックリード）、企画・営業側には企画責任者
  • 事業立ち上げと初期の顧客折衝はグループマネージャーが主導

【入社後の流れ】

  • マネージャーと並走し、店頭決済案件のリリースまでに主担当になる想定

【使用ツール・環境】

  • 会社公式AIはClaude Code（Teamプラン Premiumシートを標準付与）。仕様書・議事録・課題管理・コード調査に活用

必須条件

1. 技術ベース（最重視）

  • Web システムまたは API のソフトウェア開発の実務経験 3年以上（言語不問。Go / TypeScript 歓迎）
  • 他人が書いたコードや API 仕様書を読み、設計上の問題点や見積もりの妥当性を自分で判断できること
  • データベース、認証認可、外部 API 連携、非同期処理など、Web バックエンドの基本構成を自分の言葉で説明できること

2. プロジェクト遂行

  • 企業顧客向けのシステム開発で、仕様を決め、品質とスケジュールに責任を持ってリリースまで導いた経験 1案件以上（役割名は PM / PL / テックリードなど問いません）
  • 顧客、営業、開発など複数の関係者の間で、要件と優先順位を調整して決めた経験

3. AI 前提の働き方

  • Claude Code などのコーディングエージェントや LLM を、調査・ドキュメント作成・コード読解に日常的に使っていること
  • AI の出力の誤りを自分で見つけて直した経験

歓迎条件

  • 外部開発会社（請負または準委任）を管理し、仕様確定・見積もり査定・検収を自分で行った経験
  • 本番システムの運用保守を立ち上げた、または運用責任者を務めた経験（監視、障害対応、変更管理、顧客への報告）
  • 決済・送金・金融系システムの開発または PM 経験（決済代行、加盟店管理、精算、突合など）
  • ブロックチェーン連携システム（ウォレット、ステーブルコイン、トランザクション管理）の知識
  • 資金決済法、電子決済等代行業、暗号資産交換業などの規制対応をシステム要件に落とした経験
  • ISMS / SOC2 などの統制要件をプロジェクトに組み込んだ経験
  • 大手企業との共同開発で、先方の情報システム部門やセキュリティ部門と仕様・運用を調整した経験
  • 英語の技術ドキュメントを読めること

求める人物像

1. 開発側に立ち、事業側にも気を配れる人

  • エンジニアの言い分と事業側の要望を両方理解し、どちらにも通訳できる方
  • 決めるべきことを決め、決めた根拠を文書と数字で残せる方

2. 最後まで運ぶ人

  • リリースで終わりにせず、運用に入ってからの障害・問い合わせ・変更まで自分の責任と考える方
  • 顧客が「今回のリリースは大丈夫か」と安心して聞ける相手になれる方

3. 技術で嘘をつかれない人

  • 開発会社の「できています」を、コードとテスト結果で自分の目で確かめる方
  • 見積もりや工程表の前提を疑い、崩れる条件を先に洗い出す方

4. AI と一緒に、疑いながら速く動ける人

  • AI で調査・文書化を速く回しつつ、その出力を検証してから外に出す方
  • 速い開発サイクルの中でも、確認と説明を省かない方
